## What shipped

**Phase 1 — provider reliability.** Per-provider health tracking, `/health/providers`,
readiness reporting that never 503s on an upstream failure (a 503 there would fail Railway's
deploy healthcheck and roll back over a problem redeploying cannot fix), and a scheduled
synthetic monitor that probes the real fixture endpoint.

**Phase 2 — remaining P0 commitments.** Searchable header timezone control sharing one state
value with the filter select; verified streaming registry with official links and honest
region labelling; brand mark and a complete icon suite generated from the same geometry as
the iOS icon. Plus the Redis-backed provider registry that fixed a per-worker defect
introduced in Phase 1.

**Phase 3 — P1 correctness.** Competition country resolution; browser history restoring the
fixture the URL names; standings season configuration with a staleness tripwire; offline
snapshot trimmed of fields no client reads.

**Close-out.** Country resolution rebuilt against real provider data, and dead code removed.

**Phase 4, partial — ESPN truncation detection.** The global scoreboard request used a
hardcoded limit and never checked whether the response had been capped, so a busy day beyond
it was silently dropped while the API reported success. Verified directly against the live
provider: ESPN honours the limit and truncates silently (`limit=10` returns 10, `limit=50`
returns 50, `limit=500` and `limit=1000` both returned the true total of 73 that day), and
the payload carries no count, total or pagination field. **Provider-total detection is
therefore impossible with this endpoint** — recorded rather than faked. Coverage is now
treated as unverifiable whenever a day's response exactly fills the limit: one bounded
confirmation retry at double the limit, then a typed `PARTIAL` outcome carrying
`suspected_truncation` if it still cannot be confirmed. Verified in production on a normal
day: 67 fixtures, `state: success`, `espn` categories empty — no false positives.

## Corrections made to my own claims

Recorded because the point of this audit is that documentation matches reality.

1. **The country filter was marked `implemented` on unit-test evidence alone.** Checking
   production showed it resolved **0 of 64 fixtures** — ESPN emits `canonicalId: null` and
   uses nationality-adjective names (`English Carabao Cup`, `Venezuelan Primera División`)
   that the alias list never matched. Rebuilt against a captured real payload
   (`tests/fixtures/providers/real-competition-names.json`); now **9 of 64 fixtures across 6
   countries**, with continental competitions and friendlies correctly left unresolved.

2. **A WebKit flake was reported fixed when it was not.** A `modulepreload` change only
   perturbed the timing. The real cause was a cross-document test-isolation race, found later
   and fixed properly.

3. **Eight defects originated in the implementation plans rather than in implementation.**
   A Redis TTL that aged nothing out; MLS mapped to a single country when Toronto, Montréal
   and Vancouver are Canadian; "CBS Sports Network" aliased to Paramount+; an
   `aria-haspopup` pointing at the wrong role; a fixture dict mutated while shared between
   two branches; an undeclared Pillow dependency that would have failed CI; a `quote()` call
   leaving a URL slash unescaped; and an incorrect premise about which payload fields the
   client reads. Each was caught at review, and the plan corrected so it could not propagate.

## Not done — remaining scope

Phases 4–7 of `docs/superpowers/plans/2026-08-05-finalization-roadmap.md` are **not**
complete. In rough priority order:

1. **Provider hardening** — truncation detection is now **done** (see above). Still open:
   one request-scoped deadline across all providers instead of a fresh one each, and a
   shared metadata cache so a metadata failure stops discarding otherwise-usable fixtures.
2. **Calendar** — a bounded range endpoint, per-day partial failure handling, and score
   reveal without refetching.
3. **Team intelligence** — typed partial states, a server-side analysis cache, expanded
   verified mappings.
4. **Global search** and the **protected operations dashboard**.
5. **Mobile-first pass** from 320 px, including a known accessibility defect recorded during
   Phase 3: `reflectCurrentResults`' unconditional `matchContext.rerender()` destroys focus
   inside the match panel on **every** filter, sort or toggle re-render, so a keyboard user
   loses their place whenever anything changes.
6. **OpenAPI contract**, SLOs, analytics, the notifications ADR (which gates whether APNs is
   ever in scope), SEO, release governance, and the marketing workspace.

## Known limitations shipped deliberately

- **Country coverage is partial.** 6 of 12 distinct competitions on a sample day resolve.
  Continental competitions have no single country and are excluded on purpose; `Copa do
  Brasil` is Brazilian but carries no nationality adjective and was not contorted into the
  prefix mechanism.
- **Bare aliases `bundesliga`, `serie a`, `premiership`** also name competitions in Austria,
  Ecuador and Northern Ireland. Canonical-ID precedence limits the exposure. Recorded in the
  data file's own `note`.
- **`/health/providers` entries expire after 900 s.** On low traffic the endpoint reports
  `unknown` between fixture requests. That is honest — we genuinely do not know — but it
  makes the monitor's providers probe uninformative much of the time.
- **The standings staleness tripwire fires 2027-07-03.** When it does,
  `tests/test_standings_seasons.py` fails by design and someone must re-verify the six
  SofaScore season identifiers. That is the intended behaviour, not a bug.
